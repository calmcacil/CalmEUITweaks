# Calm UI Tweaks Review

Date: 2026-10-19
Target: CalmUITweaks 0.5.0, interface 16001
Host: EllesmereUI 9.6.1, Plugin API v1
Review type: compatibility and best-practices review; no feature Lua changes

## Findings

### P2 - WhatsTraining depends on undocumented EUI skin helpers

References: `compatability/WhatsTraining.lua:30`,
`compatability/WhatsTraining.lua:62`, `compatability/WhatsTraining.lua:1096`.

The bridge queries `GetBlizzWindowStyle` and hooks EUI skin refresh functions,
including underscore-prefixed helpers. EUI 9.6.1's published Plugin API says
not to hook EUI functions or depend on underscore-prefixed fields. Its Skinning
API documents a separate versioned callback surface. These calls have no
published compatibility guarantee. If a helper is absent or changes, the patch
can report the skin as unavailable or fail to refresh after a skin change.
The documented `S.GetStyle` returns the resolved overall theme, so it may not
preserve this feature's per-window style behavior.

### P2 - Anchor features depend on undocumented EUI internals

References: `core/AnchorEvents.lua:21`, `core/AnchorEvents.lua:39`,
`functions/SpacerCorners.lua:35`, `functions/AnchorGap.lua:68`.

Anchor observation reads `_unlockRegisteredElements` and hooks EUI placement
methods. SpacerCorners also reads the private registry, while AnchorGap calls
EUI reapply and propagation helpers. The published Plugin API does not make
these fields or functions part of its stable contract and explicitly warns
against hooking EUI functions or using underscore-prefixed fields. An EUI
update can stop anchor changes from being observed or reapplied. Existing tests
mock these interfaces and cannot prove compatibility with future EUI builds.
`SPEC.md:313` already records this dependency.

### P3 - Options pages set a private divider field

Reference: `options/Pages.lua:102`.

The page builder writes `parent._showRowDivider`. This affects divider
rendering, not core options behavior, but the field is not part of the
documented plugin API and can change or disappear with EUI.

- CVar ownership tests cover reload restoration, later external writes,

## Mise Development Tools

Added `mise.toml` and `mise.lock` for Lua 5.1.5, Python 3.13.16, ShellCheck
0.11.0, and actionlint 1.7.12. Lua binaries use the pinned `dyne/luabinaries`
release assets; Windows also installs the Lua runtime DLL. The lock targets
Windows x64 and Linux x64.

The config provides `check`, `test`, and `package-check` tasks. Check scripts
accept mise-provided `LUA_BIN`, `LUAC_BIN`, and `PYTHON_BIN` values while
retaining their existing CI defaults. The package manifest and validator
exclude `artifacts/`, `mise.toml`, and `mise.lock`. `README.md`, `SPEC.md`, and
`AGENTS.md` document the one-time `mise trust` step and the Git Bash or WSL
requirement on Windows.

## Remaining Uncertainty

No in-game run was performed. Mocked tests do not establish rendering, scaling,
protected-frame behavior, or live EUIBags, LFG, anchor, and WhatsTraining
integration. No fresh BigWigs packager archive was built; package validation
used a synthetic fixture.

A broad local search briefly returned matches from sibling add-on source files.
Those matches were excluded from this review and are not used as evidence.
