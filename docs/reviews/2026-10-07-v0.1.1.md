# Post-release code review: v0.1.1

This historical review describes v0.1.1. Its findings were addressed in v0.1.2;
see [the performance fixes](2026-10-07-performance-fixes.md).

Reviewed on 2026-10-07 after GitHub release ID 405616752 shipped. Publish run
37603814438 completed successfully, and the addon ZIP, checksums.txt and
release.json were attached. The audited origin/main commit and release tag
both resolve to `88bbf5bad4a4f4c16d26bb83f9d06f856692ace5`.

The original checkout's feature branch and local main diverge from upstream
because the feature was squash-merged. Their commits are preserved. The clean
review checkout is `.release/post-release-review`, a detached Git worktree
created from fetched origin/main. All source references below refer to that
checkout, rather than the older files in the original checkout.

The review covers all 16 TOC-loaded first-party Lua files, their existing tests,
and the documented lifecycle and feature contracts. No runtime code was changed.

## Findings

### 1. [P2] Corner alignment polls even when both preferences are DEFAULT

Source: [SpacerCorners.lua:113](../../.release/post-release-review/functions/SpacerCorners.lua#L113).

Opening EUI Unlock Mode always installs an OnUpdate at line 119. The callback
executes every rendered frame and calls Run/Update at a nominal 20 Hz, regardless
of either corner preference or whether there is a usable spacer link. Update
allocates a changed table on every pass; with managed links it also rewrites
per-character baseline records even when geometry is unchanged. Existing size
hooks at line 30 continue requesting ApplySettings after a preference returns to
DEFAULT, because their callback only tests the reentrancy flag.

A probe using the existing fixture confirms that OnUpdate is installed with
both choices DEFAULT. Throttling the work does not satisfy the no-OnUpdate
requirement. Use size notifications plus notifications for anchor creation,
replacement, profile changes and editor close. Coalesce actual changes into one
deferred pass, and gate retained hooks on an active eligible managed link. If EUI
does not expose the needed anchor notification, add or verify an upstream callback
rather than retaining a polling fallback.

### 2. [P2] Anchor gaps scan the entire anchor store every rendered frame

Source: [AnchorGap.lua:85](../../.release/post-release-review/functions/AnchorGap.lua#L85).

When automatic gaps are enabled and Unlock Mode is active, OnUpdate calls Scan
every frame. Scan allocates a changed table, traverses the full anchor store,
and traverses the observed store even when nothing changed. This is restricted
to editing and defaults off, but it is a real continuous callback and fails the
requested policy. The source explicitly says native anchor creation has no
public notification API; the current implementation therefore deliberately polls.

Apply the gap when a new link is committed through a verified native mutation
hook or a new EUI notification, preserving the current exclusions and snapshot
behavior for profile loads. Verify that the callback actually covers every
anchor-creation path before removing the watcher. A repeating ticker would
retain the same underlying problem.

### 3. [P2] SimpleItemLevel routes unfiltered events through full root scans

Sources: [SimpleItemLevel.lua:28](../../.release/post-release-review/compatability/SimpleItemLevel.lua#L28),
[SimpleItemLevel.lua:528](../../.release/post-release-review/compatability/SimpleItemLevel.lua#L528),
[SimpleItemLevel.lua:565](../../.release/post-release-review/compatability/SimpleItemLevel.lua#L565),
[SimpleItemLevel.lua:594](../../.release/post-release-review/compatability/SimpleItemLevel.lua#L594).

With the bridge enabled, 21 listed events plus PLAYER_REGEN_ENABLED remain
registered, including both immediate and delayed bag updates and two item-data
completion events. The handler drops event arguments and schedules the same
Refresh for every event. Refresh traverses every existing inventory, reagent and
bank root recursively, including hidden roots and scopes turned off in settings.
Usable filters only after reaching each item button. Visible unchanged buttons
then Clear and rebuild their asynchronous item work and overlay preparation.
This also repeatedly discovers settings controls and allocates settings snapshots
and validation closures.

The subscriptions remain when all three scopes are off or optional dependencies
are missing. Coalescing only combines events before the pending zero-delay timer
fires; later bag refresh hooks or data notifications can trigger another full pass.
A fixture probe confirms an unrelated ITEM_DATA_LOAD_RESULT traverses all three
hidden roots and that BAG_UPDATE stays registered with every scope off.

Gate registration on dependencies and active scopes. Restrict scans to visible
enabled roots, use event arguments and dirty bag/slot/item sets, and refresh only
tracked items on relevant data completion. Review which immediate bag events are
needed for invalidation versus final rendering; use BAG_UPDATE_DELAYED for a
consolidated redraw where supported. Cache settings per refresh and retain valid
unchanged item/overlay state.

### 4. [P2] Chat keeps readiness subscriptions while completely idle

Source: [Chat.lua:447](../../.release/post-release-review/functions/Chat.lua#L447).

Initialize permanently registers PLAYER_ENTERING_WORLD, PLAYER_REGEN_ENABLED,
CHANNEL_UI_UPDATE and CHAT_MSG_CHANNEL_NOTICE. ApplySettings cancels automatic
work but never unregisters events. Consequently every relevant event still
enters an error boundary and checks settings when autoApply is false, no default
exists, or the current default has already been applied. With pending channel
work, an unrelated notice or combat end retries all required subscriptions.

A fixture probe confirms four subscriptions with automation off and no pending
work. Maintain a subscription state: world readiness until first entry when
needed, regen only for a combat-deferred operation, and channel notifications
only while joining or subscribing. Unregister once work completes or automatic
work is cancelled. Manual apply, import and preference changes must re-arm the
needed events; pending manual work must survive disabling automatic application.

### 5. [P2] Disabled spacer features still receive combat/world work and addon-load fan-out

Sources: [Spacers.lua:126](../../.release/post-release-review/functions/Spacers.lua#L126),
[SpacerCorners.lua:143](../../.release/post-release-review/functions/SpacerCorners.lua#L143),
[AnchorGap.lua:122](../../.release/post-release-review/functions/AnchorGap.lua#L122),
[Lifecycle.lua:38](../../.release/post-release-review/core/Lifecycle.lua#L38),
[WhatsTraining.lua:1141](../../.release/post-release-review/compatability/WhatsTraining.lua#L1141).

Spacers and spacer corners permanently register PLAYER_REGEN_ENABLED and
PLAYER_ENTERING_WORLD, and apply settings on every delivery, including the
default fully disabled state. Spacers has a pending flag but does not consult it
in its event handler. Enabled spacers can therefore redo placement/reapply after
unrelated fights. Anchor gaps likewise retain their world event while disabled.

The core forwards every later ADDON_LOADED to every module. Spacers, corners and
anchor gaps ignore the loaded addon name and each request ApplySettings;
WhatsTraining ignores it and requests a theme pass whenever its toggle is on.
Unrelated load-on-demand addons thus trigger geometry and theme work after the
required dependencies are already established. SimpleItemLevel does filter its
OnAddonLoaded names, demonstrating the available pattern.

Keep shared ADDON_LOADED delivery for actual late dependencies, but filter module
handlers or remove resolved dependency listeners. Arm combat-end handling only
for deferred work. Keep world/profile handling only for active features or a
specific unresolved readiness state, and skip geometry application when the
effective inputs did not change.

### 6. [P2] Spacer dependency recovery never installs a missing editor-close listener

Source: [Spacers.lua:131](../../.release/post-release-review/functions/Spacers.lua#L131).

RegisterUnlockModeListener is attempted only in Initialize. If this API is
unavailable then and appears later, subsequent ApplySettings recovers spacer
registration but never installs the listener. A setting applied while Unlock
Mode is active sets pending and promises to apply on close, but no close callback
exists. It waits for a later world or combat event instead.

A probe temporarily withholds the listener API during initialization, restores
it, changes a spacer setting during editing, and closes editing. The spacer
remains unregistered until PLAYER_ENTERING_WORLD is fired. Move listener setup
into an idempotent dependency-recovery path keyed to the current EUI host. Add a
regression covering a late listener API and editor-close completion, not merely
late RegisterUnlockElements availability.

### 7. [P3] Chat and macro queue fallbacks still register one-shot OnUpdate handlers

Sources: [Macros.lua:108](../../.release/post-release-review/functions/Macros.lua#L108),
[Chat.lua:441](../../.release/post-release-review/functions/Chat.lua#L441).

If C_Timer.After is unavailable, both queues fall back to OnUpdate. These
handlers remove themselves on first invocation, so they are bounded deferrals,
not sustained gameplay polling. They nevertheless fail a literal zero-OnUpdate
policy. Core RequestApply and the compatibility queues already require
C_Timer.After, so these fallbacks do not provide complete support for a client
without the timer API.

Make the timer API part of the explicit client contract or provide an appropriate
event-based/synchronous fallback with a clear reentrancy policy. Remove the
OnUpdate registrations and their obsolete cleanup paths. Add a source-level
policy check that rejects actual OnUpdate registrations, repeated timer APIs and
self-rescheduling polling, while allowing bounded event-triggered deferrals.

## Callback and event inventory

| Component | Registrations / repeating behavior | Assessment |
| --- | --- | --- |
| Core lifecycle | ADDON_LOADED, PLAYER_LOGIN; per-module coalesced After(0) | Login unregisters normally; addon dispatch needs module filtering. Late-load Start does not itself unregister the already-fired login event. |
| Fonts | ADDON_LOADED until SharedMedia registration succeeds | Correct one-time cleanup; all events removed after registration. |
| Mage macro | Six events while enabled on a mage | Disable and non-mage cases remove all events; spell results filter awaiting IDs. Combat-end and spell-result listeners could be armed only while pending. UPDATE_MACROS is useful for ownership/conflict changes. Queue has a one-shot OnUpdate fallback. |
| Chat | Four permanently registered readiness events | Needs state-dependent registration; queue has one-shot OnUpdate fallback. |
| Spacers | World and combat-end plus Unlock Mode listener | Needs active/pending gating and late listener installation. |
| Spacer corners | World and combat-end, size hooks, Unlock Mode listener | Continuous OnUpdate during editing even with DEFAULT choices. |
| Anchor gaps | World, Unlock Mode listener | Full-store OnUpdate scans during enabled editing. |
| SimpleItemLevel | 22 attempted events while enabled, root/button/settings hooks | No explicit OnUpdate, but broad events and full scans; cleanup on disable generally works, retaining regen only for protected restoration. |
| WhatsTraining | World while enabled, page/row/native-style hooks | No first-party OnUpdate or repeating timer; world unregisters on disable. Addon-load refresh is unfiltered. Text writes refresh just the changed label; theme properties/layout have partial caches. |
| Options, commands, settings | User actions and explicit status refreshes | No event frame, polling loop or repeating timer. Status refresh visits cached labels, including cached pages. |

Four code paths register a non-nil OnUpdate: two continuous edit-mode watchers
and two one-shot fallbacks. No first-party NewTicker, NewTimer, recurring timer
or explicit self-rescheduling polling chain was found. The five C_Timer.After
queue sites are bounded, coalesced deferrals triggered by events, hooks or user
actions, rather than timer loops.

WhatsTraining's own finite hover animation is represented by an OnUpdate in its
test fixture. The bridge preserves its completion and does not install that
handler itself. Eliminating third-party native animation scripts would require
additional scope and inspection of those addons; the first-party audit cannot
establish that the entire WoW UI contains no OnUpdate handlers.

## Validation and limitations

- `scripts/check.py` passed for source version 0.1.1.
- Lua 5.1 loadstring syntax validation passed for all 26 production/test files.
- All 10 existing suites passed: AnchorGap 81 checks; Chat 117; Core/Media/Options
  72 tests; Macros 54 checks; SimpleItemLevel 105 assertions; Smoke 30 assertions;
  SpacerCorners 68 checks; Spacers 15 tests; WhatsTraining 130 assertions;
  WhatsTrainingTheme 188 assertions.
- Executed suites with Lupa 2.8's Lua 5.1 runtime in isolated environments. A
  temporary runner remaps the fixtures' CalmEUITweaks/ path prefix for this
  checkout and converts os.exit into a test failure. Production source is loaded
  unchanged. Temporary tooling lives under the original checkout's ignored
  `.release/` directory; no global runtime installation was changed.
- Additional in-memory fixture probes establish the idle corner watcher, hidden
  SIL root scans and disabled-scope event registration, idle chat subscriptions,
  and missing late spacer listener. These are call-count/state observations,
  not CPU benchmarks.
- The release workflow independently passed its source/syntax/regression and
  package checks. Shellcheck/actionlint were not rerun locally; the shell and CI
  workflows were not modified by this review.
- No live WoW execution, protected-frame behavior, taint diagnostics, third-party
  anchor mutation coverage or CPU profiling was performed. Existing fixtures do
  not assert zero OnUpdate globally, state-dependent event registration, or a
  refresh budget for unrelated events and hidden roots.

The requested no-OnUpdate policy is not met by v0.1.1. The next change should
remove the two continuous watchers, narrow SimpleItemLevel's refresh work and
subscriptions, and make idle lifecycle listeners conditional, then remove the
one-shot fallback registrations and verify behavior in WoW.
